## 经典字符串匹配问题

要求在一个较长的 $n$ 个字符的字符串（称为**文本**）中，寻找一个给定的 $m$ 个字符的字符串（称为**模式**）。

---

## 1. 暴力法

简单地从左到右比较模式和文本中每一个对应的字符，如果不匹配，把模式向右移动一个单位，再进行下一轮尝试，最差效率为 $O(mn)$。

参考下图：

![1.png](1.png)

### 代码实现
```python
def brute_force(text, pattern):
    """暴力匹配算法"""
    n, m = len(text), len(pattern)
    
    for i in range(n - m + 1):
        j = 0
        # 匹配模式的每一个字符
        while j < m and text[i + j] == pattern[j]:
            j += 1
        if j == m:
            return i  # 找到匹配
    return -1  # 未找到
```

---

## 2. 由暴力法引发的思考——Horspool算法

### 2.1 第一种优化

在暴力法中，对于文本中的每一个字符，我们让其都遍历了一次模式。换句话说，文本中的任意一个字符都和模式中的所有字符比较过，因为模式每一次都只是移动一个单位。

这些比较中，一定存在**非必要的比较**！请看如下例子：

在第一个图中，我们进行了如下比较：

![2.png](2.png)

此时文本中的 $H$ 对应模式中的 $R$。按照暴力法，由于两者不匹配，模式需要移动一个单位，如下图：

![3.png](3.png)

但是仔细观察一下，模式 $NLR$ 中根本就没有 $H$。这种移动比较是没有意义的，所以我们应该直接跳过 $H$，来到下图的情形：

![4.png](4.png)

由此我们得到**第一种优化方式**：

> 根据文本和模式尾部对齐的字符 $c$，如果模式中不含 $c$，模式安全移动的距离就是它的<span style="color: red;">**全部长度 $m$**</span>。

---

### 2.2 第二种优化

如果模式中包含字符 $c$ 呢？我们来看下图情形：

![5.png](5.png)

字符 $L$ 确实在模式中，并且不是模式的最后一个字符，那么我们一定考虑将两个 $L$ 对齐。但是这个例子的问题在于：模式里面有两个 $L$，应该对齐哪一个？

很显然，要对齐**最右边的** $L$，这样可以不漏掉所有情况。看下图情形就能够明白：

![6.png](6.png)

在这种情况下，显然我们只要移动一位，就能得到答案，也就是最右边的 $L$ 和文本中的 $L$ 对齐。

由此，得到**第二种优化方式**：

> 模式中存在 $c$，并且 $c$ 在模式中不是最后一位，可以将模式移动到<span style="color: red;">**最右的 $c$ 与文本中的 $c$ 对齐**</span>。

---

### 2.3 第三种优化

接着第一种优化的思路：如果文本中的 $c$ 是模式中的最后一位，并且模式中不含有其他的 $c$ 呢？

参考下图情形：

![7.png](7.png)

不难发现，与第一种优化一样，直接移动模式长度 $m$，因为文本中的 $R$ 在模式中除了最后一位根本不存在，就没有比较的意义。

由此，得到**第三种优化**：

> 模式中含有 $c$ 且只是最后一位，模式移动 $m$ 单位。

---

### 2.4 第四种优化

类似第二种优化思路，如果模式与文本末尾对齐 $c$，并且模式中除了末尾外还有其他 $c$，我们可以直接得到优化思路。

**第四种优化思路**：

> 模式与文本末尾对齐 $c$ 并且模式含有多个 $c$，可以将模式移动到最右面的 $c$ 与文本 $c$ 对齐。

---

### 2.5 最终优化结论

根据上述四个性质，可以总结出下列公式：

设 $c$ 是文本中的任意字符，$t(c)$ 表示模式的末尾与 $c$ 对齐时需要直接移动多少距离。

$$
t(c) = \begin{cases}
m & \text{如果 } c \text{ 不包含在模式的前 } m-1 \text{ 个字符中} \\
\text{模式前 } m-1 \text{ 个字符中最右边的 } c \text{ 到模式最右一个字符的距离} & \text{如果 } c \text{ 包含在模式的前 } m-1 \text{ 个字符中}
\end{cases}
$$

**注意**：不包含模式的最后一个字符。

这样文本中每一个字符都可以计算出一个移动值。

**例如**：模式 $BARBER$

可以得到：$t(E) = 1$，$t(B) = 2$，$t(R) = 3$，$t(A) = 4$

### 2.6 代码实现（Horspool算法）

接下来，我们用代码实现上述过程：

#### (1) 建立模式移动表
```python
def shift_table(pattern):
    """构建移动表"""
    m = len(pattern)
    table = {}
    
    # 只考虑模式的前 m-1 个字符
    for i in range(m - 1):
        # 从左向右遍历，如果字符重复出现，后面的值会覆盖前面的值
        # 这正好满足"最右字符"这一要求
        table[pattern[i]] = m - 1 - i
    
    return table
```

#### (2) Horspool匹配算法
```python
def horspool_matching(pattern, text):
    """
    Horspool字符串匹配算法
    
    参数:
        pattern: 模式串
        text: 文本串
    
    返回:
        匹配的起始位置，未找到返回-1
    """
    m = len(pattern)
    n = len(text)
    
    # 构建移动表
    table = shift_table(pattern)
    
    i = m - 1  # 文本中模式末尾对齐的位置
    
    while i < n:
        k = 0  # 已匹配的字符个数
        
        # 从右向左进行匹配
        while k < m and pattern[m - 1 - k] == text[i - k]:
            k += 1
        
        if k == m:  # 匹配个数等于模式长度
            return i - m + 1  # 返回模式起始位置
        else:
            # 根据文本中与模式末尾对齐的字符决定移动距离
            # 如果该字符不在移动表中，默认移动 m 个单位
            i += table.get(text[i], m)
    
    return -1  # 未找到匹配
```

---

### 2.7 时间复杂度分析

**最坏情况**：$O(mn)$
- 当模式和文本有大量重复字符时，例如模式为 `AAAA`，文本为 `AAAAAAAAAB`
- 每次匹配都要比较 $m$ 个字符，但只能移动 1 个单位

**平均情况（随机文本）**：$O(n)$
- 在随机文本中，失配通常发生在第一次或前几次比较
- 每次可以跳过多个字符（平均跳过 $m$ 个字符）
- 因此总比较次数接近 $\frac{n}{m}$，复杂度为 $O(n)$

**空间复杂度**：$O(\sigma)$，其中 $\sigma$ 是字符集大小（移动表的大小）

## 总结

Horspool算法已经可以高效地解决字符串匹配问题。但是Horspool算法只是另一种算法——**Boyer-Moore (BM)** 算法的简化版。

BM算法在Horspool的基础上增加了**好后缀规则**，理论上更加严谨，但实现也更加复杂。想了解更加完整的BM算法，敬待下一篇文章：
